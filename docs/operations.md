# 前日・当日の運用

## 既存VPSへの設置

新しいVPS契約は必須ではありません。既存のVPS（VPN経由で利用しているサーバーを含む）に当日版専用ディレクトリ、2つのNodeプロセス、別ポート（例3101/3102）、それぞれの非公開データ保存先を用意します。研究版のポート・`.env`・データは流用しません。CPU・メモリ・ディスクに余裕があるか確認してください。1対1のガイド生成はPython/モデル用のメモリが必要です。

1. 当日版ディレクトリを配置し、READMEに従い `npm ci` とPython環境を作成。参照元の写真・`.env`・node_modules・`.git`・仮想環境・キャッシュはコピーしない。
2. 両 `.env` に公開HTTPSルートURL、専用ポート、絶対パスの保存先、別々の運営/ワーカー資格を設定。資格は `openssl rand -hex 32` 等で新規生成し、`.env` と保存先は運営ユーザーのみ読める権限にする。
3. systemd/PM2等で各 `backend/server.js` を**1プロセスずつ**起動。データはローカル永続ディスクに置く。PM2クラスタや共有NFSは使わない。
4. HTTPSリバースプロキシを別ホスト名ごとに配置。`/ws/wiss` のUpgrade、画像アップロード20MB以上、1対1ガイド生成の応答時間140秒以上を許可。リクエスト本文・Authorization・クエリ付きURLをアクセスログへ保存しない（画像/WSのURLに参加資格が付く）。アプリのデータディレクトリを静的公開しない。
5. iOSアプリを当日用Bundle IDで署名・配布し、設定アプリに各HTTPS URLを設定。研究版とは混同しない。会場Wi-Fiからブラウザのカメラ権限とWebSocketを実機で確認。

## 設定

バックエンドは各 `backend/.env` を読み込み、明示的な環境変数が優先。設定変更後は再起動。会場PCは下記のenv-fileを使用。公開範囲・管理者・問い合わせ先・保持方針が未確認なら同意文を空のままにして共有UIを無効にする。

## Immich情報が届いたら

IP・APIキー・アルバムIDに加えて、HTTP/HTTPS、ポート、`/api`までのパス、本番バージョン、証明書とホスト名、接続可能ネットワーク、APIキーの `asset.upload` / `albumAsset.create` 権限、対象アルバムの書込権限・閲覧範囲を運営に確認します。IPだけからURLを決めつけません。自己署名CAが必要なら信頼するCAを適切に導入し、`NODE_EXTRA_CA_CERTS`等を用います。`NODE_TLS_REJECT_UNAUTHORIZED=0`は禁止。

2026-11-18に公式API資料と公式OpenAPIの `uploadAsset` / `addAssetsToAlbums` を確認。実装は `POST /api/assets`（multipart、画像と日時、device ID）で `{id,status}` を検証し、`PUT /api/albums/assets` に `{albumIds:[...],assetIds:[...]}` を送って `{success:true}` を確認します。公開最新の仕様と本番バージョンの互換性は別です。運営が指定した検証用環境・検証用アルバムで応答形式と既存画像の重複時の動作を確認してください。**本番公式アルバムへの試験投稿はしないでください。**

参考：[公式API](https://api.immich.app/)、[uploadAsset](https://api.immich.app/endpoints/assets/uploadAsset)、[addAssetsToAlbums](https://api.immich.app/endpoints/albums/addAssetsToAlbums)、[公式OpenAPI](https://github.com/immich-app/immich/blob/main/open-api/immich-openapi-specs.json)。

## バックエンド送信と会場PC

VPSからImmichへ到達できる場合はバックエンドにImmich設定を置き、`IMMICH_ENABLED=true`、`IMMICH_DELIVERY_MODE=backend`。会場限定ネットワークならバックエンドを `venue` にし、Immichキーは会場PCだけに置きます。送信を保留する場合は `hold`。

会場PCへ `shared/immich-client.js`、`shared/venue-worker.js` とenvテンプレートを配置。Node.js22以上のみ必要です。

```sh
cp shared/venue-worker.env.example /private/path/venue-worker.env
# このファイルへバックエンドURL、専用ワーカー資格、Immich設定を記入
node --env-file=/private/path/venue-worker.env shared/venue-worker.js
```

1対1と1対Nはそれぞれ別のバックエンドURL・ワーカー資格・envファイル・ワーカープロセスを用意します。会場ワーカーは外向き接続だけで動きます。運営画面の「連携設定」はバックエンド側の設定状態なので、venueモードではバックエンド未設定でも会場設定済みなら動作します。会場設定の準備状況はワーカー起動ログと検証用共有で確認してください。

モード切替は運営画面で一時停止→実行中ジョブが終了するまで待機→ワーカー停止→設定変更・バックエンド再起動→対象ワーカー起動→再開の順。同一写真を処理中に強制切替しない。会場リース期限切れは最大30秒間隔で検出します。

## 1対Nの事前素材

公開できる横4:3の参照JPEG/PNGと同じ寸法の透過PNG3種類（box、silhouette、box_face）を用意します。幅320〜6000px。運営専用 `POST /api/wiss/operator/library` にBearer運営資格でmultipart送信します。フィールドは `name`、`subjectCount`（1〜6）、`rightsConfirmed=true`、`reference`、`box`、`silhouette`、`box_face`。素材登録は当日の撮影写真とは独立しています。公開ライブラリなので公開許可済みの素材だけを投入してください。素材未登録でも自由撮影できます。

## 障害・再試行

`/admin/` で運営資格を入力し、設定・配送モード・件数・要対応エラー・容量・期限超過枚数を確認。停止/再開は新しい送信開始に作用します。

- Immich未設定：予約を保持。撮影・端末保存を続ける。
- HTTP一時障害：待機して再試行。5回で要対応。権限エラーや本文失敗は要対応。
- 結果確認中：未共有とは断定しない。運営がImmich側で写真と対象アルバムを確認し、画面の「共有完了」または「再送」で解決。画像だけ存在する場合は同じキー・同じファイルの重複検出を確認してから再送する。保存済み画像IDがある場合はアルバム登録のみ再開。
- アップロード済み・未登録：ジョブと一時画像を通常期限後も保持。再送または運営による処理完了まで自動削除しない。Immich側で非公開に保持される設定か事前確認。共有サービスの設定により画像へのアクセス範囲は変わるため、非公開をアプリだけで保証しない。
- 容量上限：受信を停止して運営へ表示。ディスクを増やす、または完了済み・不要な写真の期限処理を行う。共有待ち画像を削除して容量を空けない。
- バックエンド断：オフライン撮影の継続保存・復帰同期は未実装。撮影を止めて接続復旧を待つ。

## 終了後

参加者の端末保存を案内し、セッション終了。ブラウザとiOSで参加資格をリセットしてから次の人へ渡す。共有予約は端末を閉じても継続します。

通常期限を超えた同意待ちは運営が扱いを決めます。未完了ジョブは運営が解決するまで非公開保持。アップロード済みでアルバム未登録の画像は運営が対象画像ID・所有者・重複応答履歴を確認し、再送か削除を判断します。**当日版はImmich画像を自動削除しません。重複で返された既存画像を削除しないでください。**

全ジョブ解決後、運営の保持方針に従いサービスを停止して非公開保存先全体（state.json、資格ハッシュ、同意記録、ガイド、写真）を安全に削除するか、アクセス制限した保管先へ移します。バックアップにも同じ期限を適用。APIキー・ワーカー/運営資格は運営の方針に従い失効させます。

## Together共通QRの確認

運営はTogether用 `WISS_APP_CREATOR_TOKEN` をランダムに生成し、バックエンドとホストiOS設定へ配置する。資格の抽出やコピーに対するアプリ真正性検証は未実装。会場ではホスト端末を被写体として運用し、同端末の別ブラウザから撮影者として追加参加しない。

参加者はスマートフォン標準カメラで共通QRを開き、撮影者／被写体を選ぶ。アプリのインストールは不要。撮影者は遷移先で参加を確定してカメラを開始する。被写体はブラウザを閉じても、同じブラウザの参加情報を消さなければ再接続可能。別セッションへ切り替える前に写真保存・共有確認を済ませる。シミュレーターのlocalhost QRは別のスマートフォンから到達できないため、実機確認時は全端末が到達できるHTTPS URLを `WISS_PUBLIC_URL` に設定する。
