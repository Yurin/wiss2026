# 当日版の確定仕様

> WISS Pairは通常撮影UIを復元した版へ変更しています。Pairについては [現行手順](../WISS-Pair/README.md) を優先してください。本資料の旧Pair API・共有・運営画面の記述は適用されません。Togetherの仕様・手順は変更ありません。

この仕様が当日版の有効な製品仕様です。`docs/archive/` はローカルにのみ残す研究版・旧実装の参考資料で、Gitには含みません。

## 撮影

- 1対1：被写体1人＋撮影者ブラウザ。縦3:4、保存900×1200、ガイドも900×1200。既存の人物枠・主要ポイント・シルエット画像処理、切り抜き範囲編集を残す。正規化した画面幅・高さに対する移動、倍率、濃さを共有。ガイドは写真に焼き込まない。
- 1対N：作成用資格を設定したアプリだけがセッション作成。作成者は被写体に固定。共通QRからブラウザで役割を選択し、被写体は作成者を含め最大6人、撮影者は1人、代表者変更、事前参照写真・透過フレームの表示・提案・確定、自由撮影。横4:3、保存1600×1200。ガイドは写真に焼き込まない。
- ライブ映像は認証済みWebSocketで撮影者から被写体へ配信。状態はWebSocketと定期GETで更新。接続し直しても資格を引き継ぐ。
- 撮影画像を一時保存後、撮影者が写真確定または削除。確定後は被写体端末保存・ブラウザダウンロードが可能。共有受付前の写真は被写体も一時保存から削除可能（全員の一覧から消える）。受付後は再試行中の写真を壊さないよう参加者削除を拒否し、運営への相談を表示。
- セッション終了で撮影と映像配信を停止。保存済み写真と共有状況は既存資格で取得可能。

## 公式共有と同意

初期状態は未共有。端末保存と共有予約は別API・別操作。研究利用への同意、評価、アンケート、条件・試行管理、CSV、研究分析ログ、Google Drive、OAuth、SMTP、研究者へのフレーム作成通知は当日版に含まない。1対Nの当日写真は素材へ転用しない。

写真ごとに撮影時点の被写体IDを固定し、回答者ID、回答日時、真偽、同意文全文・バージョンを保存する。クライアントが表示した説明のバージョンとサーバー設定が一致する場合だけ回答を受理。撮影者による代理回答と後から参加した人の回答は拒否。再接続や通信切断で同意対象を減らさない。不同意が1人でもあれば送らない。初回回答後の変更は受理しないため、共有済み写真の取り下げは運営へ相談する。

説明文未設定時は共有選択を無効化。公開範囲や保持期間を仮の確定情報で埋めない。Immich未設定でも説明文が確定済みなら同意受付・共有予約が可能。

## 永続化・状態

`shared/store.js` が非公開保存先の `state.json` を一時ファイル＋fsync＋renameで保存。セッション、資格のハッシュ、写真、同意、ジョブ、運営停止状態を保持する。**保存先ごとにNodeプロセスは1つ**（クラスタ・複数レプリカ禁止）。写真・ガイドは `assets/` に保持。公開静的配信に含めない。

写真ID単位で1ジョブ。同じ撮影IDの再送は同じ写真を返す。Immich画像IDをアップロード直後に永続化し、以後はアルバム登録から再開。HTTPと本文を検証し、認証先のリダイレクトには追従しない。重複応答の既存画像を削除しない。

|画面|内部状態|扱い|
|---|---|---|
|未共有|not-shared|送信なし|
|同意待ち|awaiting-consent|全員回答待ち|
|共有予約済み|queued / pending|設定・送信開始待ち|
|写真送信中|uploading / running|アップロード処理|
|アルバム登録中|album-adding / running|画像ID保存済み|
|共有完了|complete / succeeded|登録確認済み|
|再試行待ち|retry / failed|一時障害、指数バックオフ|
|結果確認中|uncertain|通信中断等。送信済みの可能性あり|
|運営対応|attention|権限・本文エラー・再試行上限|

HTTP 5xx/429は5秒から最大1時間まで待機して再試行。既定上限5回。通信断・タイムアウトで結果不明なら結果確認中へ移し、運営確認まで自動再送しない。再起動で処理中だったバックエンドジョブは、画像IDありならアルバム再試行、なければ結果確認中。会場ジョブはリース期限まで他プロセスに割り当てず、期限後に同様に復旧する。

## 保存とアクセス

写真取得・状態照会にはセッション資格、運営APIには運営資格、会場APIには別のワーカー資格を要求。APIキーは送信するサーバーまたは会場PCの環境のみ。クライアントからImmich接続先・アルバムを指定不可。運営画面にキーを返さない。参加資格を持つ同じセッションの参加者はそのセッションの写真を閲覧できる。

既定：下書き1時間、確定写真7日、容量2GiB。共有予約・再試行・結果確認中・要対応・同意待ちは通常の期限削除から除外。完了写真と未共有写真は期限後に一時ファイルを削除。運営画面に使用容量・上限・期限超過枚数を表示。上限超過時は新しい画像受信を507で拒否し、既存画像を勝手に削除しない。メタデータとガイドはイベント終了後の運営処理まで保持する。

## 会場ネットワーク

送信モード `backend` / `venue` / `hold` は排他的。`IMMICH_ENABLED=false` または運営停止中は新しい送信を開始しない（すでに実行中のHTTPは完了し得る）。会場PCはバックエンドへ外向きポーリングし、リース取得→認証画像取得→共通Immichクライアントで送信→画像ID報告→アルバム登録→結果報告。会場PCへの外部着信は不要。端末にImmichキーを配布しない。TLS検証を無効にしない。

既存バックエンドに接続できない状態でのオフライン撮影保存・復帰送信は未実装。Immichだけ到達不能なら通常撮影は継続できる。

## TogetherのUI

iOSはPairと同じ縦向きの開始画面・ボタンスタイルを使用。「セッションを作成」と「グループに参加」を分け、QR/コード入力は参加シートに表示。フレーム選択・提案・代表者変更はフォーム形式の設定画面。写真・ライブ映像・フレームの座標系は横4:3のまま維持する。

## Togetherの作成資格と共通QR

Togetherの `POST /api/wiss/sessions` は拒否する。アプリは `POST /api/wiss/app/sessions` に作成専用資格を送信し、サーバーが検証する。資格を公開JS・招待URL・QRへ含めない。これは運営がアプリへ配布する資格による制限であり、App Attest等によるアプリ真正性の検証ではない。資格をコピーした独自クライアントを排除する仕組みではない。

共通QRは `/booth/join.html#参加コード`。役割選択後、撮影者は既存の撮影画面、被写体は `/booth/subject.html` へ進む。ブラウザにセッション作成機能はない。作成者の参加資格は常に被写体であり、役割変更APIは提供しない。別アプリ・別ブラウザで同じ物理端末から新しい参加者として参加することまで端末識別で防ぐものではない。

ブラウザ被写体はライブ映像・参照フレーム・提案・代表者操作・写真保存・削除・本人の共有同意を利用可能。ブラウザの参加資格を保存し再読込・終了後も写真と共有状態を再確認できる。アプリ被写体も含め、撮影時の全員同意が共有条件。撮影者がすでにいる場合は二人目の撮影者を拒否する。
